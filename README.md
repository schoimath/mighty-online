# Mighty Club · 마이티 온라인

친구들과 방 코드를 나누고 브라우저에서 즐기는 5인 마이티입니다. [게임 열기](https://schoimath.github.io/mighty-online/)

## 플레이

1. 한 사람이 **방 만들기**를 누르고 닉네임을 정합니다.
2. 대기실의 초대 링크나 6자리 방 코드를 친구에게 보냅니다. 친구는 링크를 열거나 **방 참가하기**에서 코드를 입력합니다.
3. 방장이 **게임 시작**을 누르면 다섯 자리에 각각 10장씩 배분합니다. 빈자리는 AI가 맡습니다. **혼자 연습하기**에서는 같은 규칙을 설정하고 AI 네 명과 시작할 수 있습니다.

대기실에서 원하는 빈자리를 누르면 바로 옮깁니다. 다른 사람이 앉은 자리를 누르면 교환을 요청하고, 상대가 수락하면 두 사람이 자리를 바꿉니다. 방장이 자리를 옮겨도 방장 권한은 그대로입니다. 첫 판은 1번 자리에서 입찰을 시작합니다.

방장은 대기실의 **테이블 규칙**에서 최저 공약(13~20점), 초구 프렌드 가능 여부, 초구 조커콜 효력, 막구 조커 효력을 정할 수 있습니다. 새 방은 최저 14점으로 시작합니다. 초구 프렌드는 허용하고 초구 조커콜과 막구 조커 효력은 꺼져 있습니다. 막구 조커 효력을 켜면 마지막 트릭에서 조커가 기루다를 이깁니다. 마이티가 나오거나 조커콜이 선언되면 조커는 이길 수 없습니다. 변경한 설정은 같은 방의 다음 판에도 적용됩니다. 게임 중 **게임 규칙**에서 현재 설정을 확인할 수 있습니다.

일반 카드는 손패에서 한 번 누르면 내 자리 앞으로 나갑니다. 조커로 선을 잡을 때 조커를 누르면 손에 기루다가 없어도 기루다 무늬가 기본으로 선택됩니다. 노기루다에서는 손에 가장 많은 무늬가 기본입니다. 원하는 무늬로 바꾼 뒤 낼 수도 있습니다.

손패의 조커콜 카드에는 보라색 **조커콜** 표식이 붙습니다. 클로버 기루다에서는 ♠3, 그 밖에는 ♣3입니다. 조커콜을 선언할 수 있는 차례에 이 카드를 누르면 **조커콜**이 기본으로 체크됩니다. 그냥 내고 싶으면 체크를 해제한 뒤 카드를 냅니다.

주공에게는 카드 교환 중 바닥에서 받은 세 장이 따로 표시됩니다. 기루다가 정해지면 해당 무늬의 카드가 손패 왼쪽에 모이고, 플레이 중에는 왼쪽 위 트릭 번호 옆에서 기루다와 공약 점수를 확인할 수 있습니다. 손패와 테이블의 마이티 카드에는 금색 **마이티** 표식이 붙습니다. 스페이드 기루다에서는 다이아몬드 A, 그 밖에는 스페이드 A가 마이티입니다.

프렌드 지정은 **마이티 → 조커 → 기루다 A → 노프렌드** 순서로 기본 선택합니다. 주공 손에 있거나 묻은 카드는 건너뜁니다. 노기루다에서 마이티와 조커를 모두 가졌으면 노프렌드가 기본입니다. 주공은 확정하기 전에 다른 프렌드를 직접 고를 수 있습니다. 첫 트릭을 시작할 때 테이블 가운데에 **마이티 프렌드**, **초구 프렌드**처럼 선언한 내용이 약 2.2초 동안 한 번 뜹니다.

주공의 자리는 황금갈색, 프렌드의 자리는 파란색으로 표시합니다. 정체가 드러나기 전에는 프렌드 본인에게만 파란색이 보입니다. 공개된 점수 카드는 각자 자리 옆에 모두 펼쳐집니다. 주공의 더미는 처음부터 덮고, 프렌드의 정체가 밝혀지면 이전에 획득한 카드도 모두 덮습니다. 판이 끝나면 주공 팀의 최종 점수를 확인할 수 있습니다.

결과 화면에서 방장이 **다시 한 판**을 누르면 같은 자리와 규칙으로 바로 새 카드를 받습니다. 직전 판의 프렌드가 첫 입찰을 합니다. 노프렌드였다면 직전 주공이 먼저 입찰합니다. 새 참가자를 받거나 규칙을 바꾸려면 **대기실로 돌아가기**를 누르세요. 첫 입찰자가 대기실에서 옮겨 앉으면 바꾼 자리에서 시작하고, 떠났으면 그 사람이 앉았던 자리에서 시작합니다. 연습 게임에서도 바로 재경기하거나 규칙을 바꿔 시작할 수 있습니다.

입찰, 최종 공약, 프렌드 카드, 조커의 요구 무늬를 고를 때 ♥·♦는 빨강, ♠·♣는 검정입니다. 각자 카드를 놓는 자리에 그 사람이 마지막으로 부른 공약이나 패스가 표시되고, 가운데에는 최고 공약이 남습니다. 공약이 오르면 방 전체에 더 높은 종소리가 나고, 패스하면 낮고 짧은 음이 납니다. 같은 점수에서는 노기루다가 무늬 공약보다 반음 높습니다. AI가 첫 입찰자일 때는 약 1.8초, 이후 AI 입찰은 약 1.35초 간격을 둡니다. 마지막 공약이나 패스도 1.35초간 경매판에 표시한 뒤 바닥패를 열거나 새 패를 나눕니다.

테이블에 낸 카드는 각자 자리 앞에 원을 따라 놓입니다. 조커콜을 선언하면 그 카드에 보라색 **조커콜** 표식이 뜨고 두 음이 연달아 울립니다. 선이 낸 무늬와 다른 기루다를 내서 찍으면 카드가 탁자에 부딪히는 낮은 강조음이 납니다. 게임 상단의 스피커 버튼으로 입찰음과 카드 효과음을 함께 켜거나 끌 수 있습니다. 이 설정은 사용 중인 브라우저에 저장됩니다.

온라인 방의 **채팅**은 화면 아래쪽에 열립니다. 제목을 끌면 창이 이동하고, 모서리의 크기 조절 손잡이를 끌면 너비와 높이가 바뀝니다. 손잡이를 한 번 누르면 크게 열거나 기본 크기로 돌아갑니다. 선택한 크기는 브라우저에 저장됩니다. 대기실과 게임 테이블, 같은 방의 재경기에서 최근 메시지 60개가 이어집니다.

## 테이블 점수표

새 테이블에서는 모두 0점으로 시작합니다. 각 플레이어의 이름 옆에 누적 점수가 표시되며, 같은 방에서 자리를 옮겨도 점수는 사람을 따라갑니다. 결과 화면에는 이번 판 정산과 갱신된 누적 점수가 함께 나옵니다.

런이나 백런이면 보드 중앙에 결과가 표시됩니다. 예를 들어 프렌드가 있는 14점 노기루다 공약에서 여당이 20점을 모두 얻으면 **여당 기준점수**는 **+8점 ×2 (런) ×2 (NT) = +32점**입니다. 주공은 +64점, 프렌드는 +32점, 야당은 각각 −32점을 기록합니다. [개인 정산식과 배율](RULES.md)

처음 받은 10장에 점수 카드(10·J·Q·K·A)가 한 장도 없는 사람이 있으면 공약 전에 자동으로 파토 처리해 다시 나눕니다.

## 컴퓨터 플레이어

새 방이나 연습 게임에서는 자리마다 아래 세 모델 중 하나를 독립적으로 뽑습니다. 같은 모델이 여러 자리에 앉을 수 있습니다. 대기실과 연습 설정에서 **전체 AI 모델**을 한꺼번에 바꾸거나 **자리별 AI 선택**으로 한 자리만 바꿀 수 있습니다. 같은 방에서 다시 한 판을 하거나 나간 참가자를 AI가 대신할 때도 그 자리의 모델을 사용합니다.

| 선택 | 플레이 목적 |
| --- | --- |
| 공약 탐색형 | 주공이 바닥패를 받은 뒤 같은 패 배분에서 기루다와 공약을 바꿔 가며 정산 비교 |
| 기억형 · 균형 | 이전 차례의 정보를 기억하며 팀 승리와 개인 정산점수를 함께 고려. 자기대국 학습 때 두 목표에 각각 70%, 30% 반영 |
| 협력형 | 팀원이 이기는 트릭에 점수 카드를 보태고, 팀이 질 가능성이 큰 트릭에서는 점수 카드를 아낌 |

세 모델의 승률과 판당 개인 정산점수는 이전 후보들과 같은 배분에서 비교했습니다. [모델별 대국 성적](lab/results-live/final_test.md) · [기억형 학습과 한 수 분석 재현](lab/RECURRENT.md) · [정산과 게임 규칙](RULES.md)

### 기존 탐색형의 개발 기록

이전 버전에서 학습에 쓰지 않은 패 400개로 2,000번 비교했을 때, 교체한 자리의 승률은 당시 기본 AI **53.30%**(1,066승), 개선한 AI **61.55%**(1,231승)였습니다. 바닥패 교환 방식을 양쪽 모두 고정한 결과는 **59.55%**였습니다. 현재 성적표는 일반 선 카드의 평가값 계산을 바로잡은 탐색형을 기준으로 별도 산출했습니다.

당시 학습·평가의 소스는 [개인 정산을 도입하기 전 버전](https://github.com/schoimath/mighty-online/tree/bb66cce)에 있습니다. 현재 탐색형의 전술 가중치 실험은 `node train-bot.mjs train`, 카드 내기 평가는 `node train-bot.mjs evaluate`, 바닥패 교환 평가는 `node train-bot.mjs evaluate-exchange`로 실행합니다.

## 실시간 연결

GitHub Pages가 화면과 게임 코드를 제공합니다. 참가자는 PeerJS의 공개 연결 서비스(PeerServer Cloud)를 통해 방장을 찾은 뒤 WebRTC 데이터 채널로 게임 상태를 주고받습니다. 방장의 브라우저가 손패를 배분하고, 연결된 자리와 차례를 확인한 후 각 참가자에게 개인 손패와 공개 정보만 보냅니다. [PeerJS 문서](https://peerjs.com/docs/)

방장은 한 판이 끝날 때까지 탭을 열어 두어야 합니다. 방장이 나가거나 새로고침하면 방이 닫힙니다. 진행 중에 다른 참가자가 나가면 AI가 해당 자리를 이어받습니다. 같은 방의 다음 판에는 대기실에서 다시 참가할 수 있습니다. 온라인 방에는 WebRTC와 신호 서버에 연결할 수 있는 네트워크가 필요합니다.

## 로컬 실행

Node.js 22 이상에서 별도 패키지 설치 없이 실행할 수 있습니다.

```sh
npm start
```

브라우저에서 [로컬 게임](http://127.0.0.1:4173/)을 엽니다. 게임 규칙과 세션 검증은 `npm test`로 실행합니다.

GitHub Pages 배포 원본은 `main` 브랜치의 루트입니다. 정적 파일을 수정해 푸시하면 사이트가 갱신됩니다. 배포용 PeerJS 1.5.5와 라이선스는 `vendor/peerjs-1.5.5/`에 포함되어 있습니다.
